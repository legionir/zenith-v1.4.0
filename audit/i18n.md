# گزارش حسابرسی پکیج `i18n`
**نسخه:** v1.3.0 | **بسته:** `@zenith/i18n`

---

## ۱. خلاصه پکیج

پکیج `i18n` ابزارهای بین‌المللی‌سازی (بومی‌سازی) فریم‌ورک Zenith را فراهم می‌کند. این پکیج با تمرکز بر زبان فارسی طراحی شده و شامل توابع تبدیل اعداد به فارسی/عربی (`toPersianNums`, `toArabicNums`)، تبدیل تاریخ میلادی به جلالی (`toJalali`, `fromJalali`)، فرمت تاریخ (`formatJalali`)، فرمت اعداد و قیمت، تشخیص RTL و مقایسه تاریخ جلالی است.

## ۳. باگ‌ها و مشکلات

### BUG-I18N-01: `toJalali` با تاریخ‌های قبل از ۱۶۰۰ میلادی (BUG-07) همچنان ممکن است مشکل داشته باشد
- **شدت:** بالا
- **محل:** `src/index.ts` – BUG-07 fix
- **شرح:** BUG-07 برای تاریخ‌های قبل از ۱۶۰۰ میلادی guard اضافه کرده اما اگر سال بسیار قدیمی باشد (مثلاً ۵۰۰ میلادی)، الگوریتم تبدیل جلالی ممکن است به دلیل تغییرات تقویم تاریخی نادرست باشد.
- **نحوه رفع:** بازگرداندن `null` برای تاریخ‌های خارج از محدوده پشتیبانی:

```typescript
export function toJalali(date: Date): JalaliDate | null {
  const year = date.getFullYear();
  // تقویم جلالی فقط برای سال‌های ۱۱۷۸ به بعد (تقریباً ۶۲۲ میلادی به بعد)
  if (year < 622) return null;

  // ادامه محاسبه
}
```

### BUG-I18N-02: `formatJalali` با BUG-5 fix (MMMM قبل از MM) ممکن است locale-specific باشد
- **شدت:** کم
- **محل:** `src/index.ts` – BUG-5 fix
- **شرح:** تابع `formatJalali` با یک replace ساده کار می‌کند. اگر الگوی فرمت شامل رشته‌هایی باشد که با placeholders اشتباه گرفته شوند (مثلاً "MMMM" بخشی از یک کلمه)، جایگزینی نادرست رخ می‌دهد.
- **نحوه رفع:** استفاده از regex با word boundary یا جایگزینی ترتیبی:

```typescript
export function formatJalali(date: JalaliDate, format: string): string {
  return format
    .replace(/\bYYYY\b/g, String(date.year))
    .replace(/\bMM\b/g, String(date.month).padStart(2, '0'))
    .replace(/\bMMMM\b/g, jalaliMonthName(date.month))
    .replace(/\bDD\b/g, String(date.day).padStart(2, '0'))
    .replace(/\bDDDD\b/g, String(date.day));
}
```

### BUG-I18N-03: `addDaysJalali` با BUG-04 (Date copy) اگر date null باشد
- **شدت:** متوسط
- **محل:** `src/index.ts` – BUG-04 fix
- **شرح:** BUG-04 برای کپی صحیح Date رفع شده اما اگر date ورودی null یا undefined باشد، خطای TypeError رخ می‌دهد.
- **نحوه رفع:** guard در ابتدای تابع:

```typescript
export function addDaysJalali(date: Date | null, days: number): Date | null {
  if (!date || !(date instanceof Date) || isNaN(date.getTime())) {
    console.error('[Zenith] Invalid date passed to addDaysJalali');
    return null;
  }
  const result = new Date(date.getTime()); // BUG-04 fix
  result.setDate(result.getDate() + days);
  return result;
}
```

### BUG-I18N-04: `isRTL` با 3-source check (v1.2.3) ممکن است false negative بدهد
- **شدت:** کم
- **محل:** `src/index.ts` – v1.2.3 fix
- **شرح:** سه منبع برای تشخیص RTL بررسی می‌شود اما اگر مرورگر با زبان RTL اجرا نشود و هیچ dir attributeای روی HTML نباشد، تشخیص RTL برای متن فارسی نادرست است.
- **نحوه رفع:** افزودن بررسی text direction با canvas:

```typescript
export function isRTL(text?: string): boolean {
  // بررسی‌های موجود
  const htmlDir = document.documentElement.getAttribute('dir');
  if (htmlDir === 'rtl') return true;

  // بررسی با canvas برای تشخیص واقعی کاراکترهای RTL
  if (text) {
    const rtlChars = /[؀-ۿݐ-ݿࢠ-ࣿﭐ-﷿ﹰ-﻿]/;
    if (rtlChars.test(text)) return true;
  }

  return false;
}
```

### BUG-I18N-05: `parseJalaliParts` با ورودی نامعتبر null برمی‌گرداند (v1.2.3) اما callers بررسی نمی‌کنند
- **شدت:** کم
- **محل:** `src/index.ts` – v1.2.3 fix
- **شرح:** `parseJalaliParts` برای ورودی نامعتبر `null` برمی‌گرداند (رفع v1.2.3). اما فراخوان‌هایی که از این تابع استفاده می‌کنند ممکن است null را بررسی نکنند و با TypeError مواجه شوند.
- **نحوه رفع:** افزودن null check در callers یا استفاده از optional chaining.

## ۴. پیشنهادات ارتقا

### IMP-I18N-01: افزودن `formatRelative` برای زمان‌های نسبی
- **دلیل:** نمایش «۲ ساعت پیش»، «دیروز» و...

```typescript
export function formatRelative(date: Date, base?: Date): string {
  const diff = (base ?? new Date()).getTime() - date.getTime();
  const minutes = Math.floor(diff / 60000);
  const hours = Math.floor(minutes / 60);
  const days = Math.floor(hours / 24);

  if (minutes < 1) return 'همین الان';
  if (minutes < 60) return `${minutes} دقیقه پیش`;
  if (hours < 24) return `${hours} ساعت پیش`;
  if (days < 7) return `${days} روز پیش`;
  // ...
}
```

## ۶. نتیجه‌گیری کلی
