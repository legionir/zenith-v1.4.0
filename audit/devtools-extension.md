# گزارش حسابرسی پکیج `devtools-extension`
**نسخه:** v1.3.0 | **بسته:** `@zenith/devtools-extension`

---

## ۱. خلاصه پکیج

پکیج `devtools-extension` افزونه مرورگر Chrome برای فریم‌ورک Zenith است که امکان بررسی و دیباگzing سیگنال‌ها، ایفکت‌ها، دستورات، DOM، کامپوننت‌ها،および依存グラフ را提供します。

主要な機能：
- **popup.html/popup.js**: DevToolsパネルのUI（5つのタブ: Signals, Timeline, Components, Effects, v1.0 Features, Graph）。
- **background.js**: サービスワーカー - 拡張機能のインストールを処理し、DevToolsパネルを作成し、コンテンツスクリプトからの通知をリッスンします。
- **content.js**: コンテンツスクリプト - `window.__ZENITH__` フックと通信し、ポップアップにデータを送信します。
- **devtools.html/devtools-panel.js**: Chrome DevTools パネル内のカスタムタブ（ポップアップと同じ UI を表示します）。
- **graph-viewer.html**: 依存グラフのスタンドアロンビューアー（ライブデータ、サンプルデータ、またはクエリパラメータからデータを読み込む）。
- **manifest.json**: Chrome 拡張機能のマニフェスト。

この拡張機能は、`@zenith/devtools` パッケージによって提供される `window.__ZENITH__` フックに依存しており、ランタイムからシグナル、エフェクト、ディレクティブ、DOM、サーバーコンポーネントの統計などのデータを取得します。

## ۳. باگ‌ها و مشکلات

### BUG-DEVTEXT-01: グラフビューアのライブデータ取得における潜在的な XSS
- **schwere Wassermittel:**
- **Miejsce:** `packages/devtools-extension/graph-viewer.html` - `loadSnapshot()` 関数、行273-296
- **説明:** グラフビューアは、ライブデータのために `window.__ZENITH__.getDependencyGraph()` を試みます。返されたデータはそのまま `setData()` に渡され、最終的に SVG 内にレンダーされます（ノードラベルなど）。ただし、返されたデータがサニタイズされていない場合（例えば、ノードのラベルに HTML が含まれていると）、SVG 内にスクリプトを挿入する可能性があります。現在の実装では、ノードラベルは `textContent` ではなく `textContent` プロパティを設定してテキストノードとして追加しています（行450-451、`lbl.textContent = n.label;`）、これによりスクリプトの実行は防がれます。しかし、ラベルが属性値として使用される場合（例：ツールチップ）にはリスクがあります。現在のところ、ラベルはテキストとしてのみ使用されているため、リスクは低いですが、今後の変更で属性に使用される可能性を考慮すると、サニタイズを追加する方が安全です。
- **提案の修正:** ノードラベルやその他のユーザー提供文字列が SVG 属性に使用される場合は、サニタイズを追加してください（たとえば、`escapeHtml` 関数を使用）。現在の実装ではテキストノードとして設定しているため、直ちのリスクはありませんが、将来の変更に備えてコメントを追加してください。

### BUG-DEVTEXT-02: ポップアップの自動更新間隔がハードコーディングされている
- **schwere Wassermittel:**
- **Miejsce:** `packages/devtools-extension/popup.js` - 行47-48
- **説明:** ポップアップは `setInterval(fetchData, 2000)` を使用して2秒ごとにデータを取得します。この間隔はハードコーディングされており、ユーザーがカスタマイズできません。特定のシナリオでは、この頻度が高すぎたり低すぎたりする可能性があります（例えば、バッテリー駆動のデバイスでは頻繁な更新がバッテリーを消費し、またはリアルタイムのデバッグでは遅すぎる可能性があります）。
- **提案の修正:** 更新間隔を設定可能にする（例えば、ポップアップの設定メニューを追加するか、または `localStorage` を使用して最後に設定された間隔を記憶する）。あるいは、変更が発生したときのみ更新するプッシュベースのメカニズム（例えば、ランタイムからのカスタムイベント）を検討してください。

### BUG-DEVTEXT-03: コンテンツスクリプトにおける誤った `sendResponse` の使用
- **schwere Wassermittel:**

- **提案の修正:** `sendResponse` を呼び出す代わりに、リッスナーから `true` を返して非同期応答を示す（ただし、ここでは非同期処理がないため、単に `sendResponse` を呼び出さずにリッスナーから `false` または何も返さない）か、または非同期処理が必要な場合は適切�してください。ここでは、すべての処理が同期的であるため、`sendResponse` を呼び出し、リッスナーから `false` を返すか、または何も返さない（デフォルトは `undefined` ですが、これは `false` と解釈されます）ように変更してください。

### BUG-DEVTEXT-04: グラフビューアのサンプルデータがハードコーディングされている
- **schwere Wassermittel:**
- **Miejske:** `packages/devtools-extension/graph-viewer.html` - 行230-265
- **説明:** グラフビューアにはサンプルデータ（デモ）がハードコーディングされています。これはデモ目的では便利ですが、実際のアプリケーションの構造を反映していない可能性があり、ユーザーに誤解を与える可能性があります。さらに、サンプルデータが古くなり、`window.__ZENITH__` フックの構造に変更が加えられた場合、サンプルデータが不整合を起こす可能性があります。
- **提案の修正:** サンプルデータを動的に生成するか、または最小限の現実的な例（例えば、単一のシグナルとエフェクト）を使用することを検討してください。あるいは、サンプルデータを削除し、ライブデータが利用できない場合は明確なメッセージを表示する。

### BUG-DEVTEXT-05: ポップアップの v1.0 フィーチャー パネルにおける潜在的なパフォーマンス問題
- **schwere Wassermittel:**
- **Miejsce:** `packages/devtools-extension/popup.js` - `renderV1Features` 関数、行242-314
- **説明:** `renderV1Features` 関数は、ポップアップの更新ごとに v1.0 フィーチャー データ（zen-static, destroyed resources, cache stats, SSR stores）をレンダーします。ただし、これらのデータセットが大きい場合（例えば、多数の zniszczone resources または多数のユニークな式）、DOM 操作が高コストになる可能性があります。特に、`destroyedResources` で、`reverse()`、およびテンプレートリングループ内で使用されています。これらは大きな配列に対して非効率的です。
- **提案の修正:** 大きなデータセットに対しては、仮想スクロールまたはページネーションを実装するか、または表示する項目数を制限する（例えば、最新の10件のみを表示）ことを検討してください。さらに、データセットが変更された場合のみ再レンダーするように最適化してください（たとえば、前回のレンダーからデータのハッシュを比較する）。

### BUG-DEVTEXT-06: グラフビューアのドラッグ機能における潜在的な問題
- **schwere Wassermittel:**
- **Miejsce:** `packages/devtools-extension/graph-viewer.html` - `enableDrag` 関数、行601-627
- **説明:** グラフビューアのドラッグ機能は、`mousedown`、`mousemove`、`mouseup` イベントリスナーを使用して実装されています。ただし、これらのリスナーはノードグループ要素（`<g>`）に追加されていますが、`mouseup` イベントは `window` に追加されています。これにより、ドラッグ中にカーソルが SVG の外に移動した場合でも、`mouseup` イベントが正しくキャッチされるため、問題は発生しません。しかし、ドラッグ中に `mouseup` イベントが発火する前にページから離れた場合（例えば、タブを切り替える）、`dragging` フラグがリセットされず、状態が不整合になる可能性があります。さらに、ドラッグ中にノードが固定位置（`fx`、`fy` が設定されている）の場合、ドラッグは無視されるべきですが、現在の実装では固定位置のノードでもドラッグを試みます（ただし、固定位置のノードでは `fx`、`fy` が `null` でないため、ドラッグは実際には位置を変更しませんが、計算は行われます）。
- **提案の修正:** ドラッグを開始する前にノードが固定位置かどうかをチェックし、固定位置の場合はドラッグを無効にしてください。さらに、`visibilitychange` または `tabchange`（または `visibilitychange` イベント）をリッスンして、ページが非表示になるときにドラッグをリセットすることを検討してください。

### BUG-DEVTEXT-07: ポップアップにおけるエラーハンドリングの不備
- **schwere Wassermittel:**
- **Miejsce:** `packages/devtools-extension/popup.js` - `fetchData` 関数、行50-78
- **説明:** `fetchData` 関数では、ランタイムからの応答が `undefined` またはエラーの場合、`statusBar` を更新し、`.empty` 要素のテキストを「—」に設定します（行56-59）。ただし、エラーの具体的な原因（例えば、ランタイムが利用できない、またはメッセージがタイムアウトしたなど）がユーザーに伝わらないため、トラブルシューティングが困難になる可能性があります。さらに、複数のエラー条件が同じ方法で処理されるため、ユーザーは問題の正確な原因を特定できません。
- **提案の修正:** エラーメッセージをより詳細にし、可能であればエラーの種類（例えば、ランタイムが見つからない、メッセージがタイムアウトした、など）を示してください。また、開発者向けにコンソールに詳細なエラーログを出力することを検討してください。

### BUG-DEVTEXT-08: マニフェストにおける過剰なパーミッション
- **schwere Wassermittel:**
- **Miejsce:** `packages/devtools-extension/manifest.json` - 行24-31
- **説明:** マニフェストでは `"host_permissions": [ "<all_urls>" ]` が宣言されており、これにより拡張機能はすべてのウェブサイトでコンテンツスクリプトを挿入できます。これは、Zenith アプリケーションが動作するドメインに限定するべきです。すべてのサイトへのアクセスはセキュリティリスクを増加させ、ユーザーのプライバシーに関する懸念を引き起こす可能性があります。
- **提案の修正:** `host_permissions` を Zenith アプリケーションが一般的にホストされるドメインに制限してください（例えば、`<all_urls>` の代わりに特定のドメインまたはパターンを指定する）。あるいは、`<all_urls>` を維持する場合は、なぜそれが必要なのかをマニフェストの説明に明記し、ユーザーに説明してください。

### BUG-DEVTEXT-09: ポップアップにおける未使用の変数
- **schwere Wassermittel:**
- **Miejsce:** `packages/devtools-extension/popup.js` - 行10-13
- **説明:** `statusBar`、`versionEl`、`refreshBtn`、`clearBtn` などの変数が宣言されていますが、`versionEl` は行65でのみ使用され、それ以外では使用されていません。さらに、`openGraphBtn` は行39-42で宣言され、行41でイベントリスナーが追加されていますが、変数自体はそれ以外では使用されていません。これにより、コードが少し読みにくくなり、未使用の変数に関する警告が発生する可能性があります（ただし、これらの変数は間接的に使用されているため、実際には未使用ではありませんが、より明確にするためにインライン化またはコメントを追加できます）。
- **提案の修正:** 未使用の変数を削除するか、または使用している場所にコメントを追加してください。例えば、`versionEl` は行65で使用されているため、コメントでその使用場所を示すと良いでしょう。

### BUG-DEVTEXT-10: グラフビューアにおけるズーム機能の欠如
- **schwere Wassermittel:**
- **Miejske:** `packages/devtools-extension/graph-viewer.html` - 全体
- **説明:** グラフビューアはパン（ドラッグ）をサポートしていますが、ズーム機能（マウスホイールまたはピンチズーム）が実装されていません。大きなグラフでは、ノードが重なって見えにくくなるため、ズーム機能があるとユーザー体験が向上します。
- **提案の修正:** マウスホイールイベントリスナーを追加し、スケールを調整してズーム機能を実装してください。また、ピンチズーム（タッチデバイス）もサポートすることを検討してください。

## ۴. پیشنهادات ارتقا

### IMP-DEVTEXT-01: 設定可能な更新間隔
- **для чего:** ユーザーが自分のニーズに応じて更新頻度を調整できるようにし、バッテリー消費やリアルタイム性のバランスを取る
- **実装:** ポップアップに設定メニュー（例えば、ギアアイコン）を追加し、更新間隔を選択できるようにする（例: 1秒、2秒、5秒、10秒、手動）。選択された間隔を `localStorage` に保存し、次回起動時に読み込む。

### IMP-DEVTEXT-02: プッシュベースのアップデートメカニズム
- **дляそのために:** ポーリングを減らし、リアルタイム性を向上させる
- **実装:** `@zenith/devtools` パッケージ側で、データが変更されたときにカスタムイベント（例えば、`zenith-data-update`）をディスパッチする。コンテンツスクリプトはこのイベントをリッスンし、変更があるときのみポップアップにメッセージを送信する。これにより、不要なポーリングが削減され、変更が即座に反映される。

### IMP-DEVTEXT-03: グラフビューアのズーム機能
- **дляそのために:** 大きなグラフの可視性とユーザー体験を向上させる
- **実装:** マウスホイールイベントリスナーを追加し、`scale` プロパティを調整してズームを実装する。また、`transform` 属性を使用して SVG グループをスケールする。ピンチズームについては、`touchstart`、`touchmove`、`touchend` イベントを処理する。

### IMP-DEVTEXT-04: エラーハンドリングの改善
- **дляそのために:** トラブルシューティングを容易にし、ユーザーに明確なフィードバックを提供する
- **実装:** `fetchData` 関数で、エラーの種類を区別し、より具体的なメッセージを表示する（例: 「Zenith ランタイムが見つかりません」、「メッセージのタイムアウト」など）。また、コンソールに詳細なエラー情報をログ出力する。

### IMP-DEVTEXT-05: ホストパーミッションの制限
- **дляそのために:** セキュリティとプライバシーを向上させ、不要なデータアクセスを防止する
- **実装:** `manifest.json` の `host_permissions` を、`<all_urls>` から Zenith アプリケーションが一般的にホストされるドメイン（例えば、`https://*.example.com/*` また� `<all_urls>` の代わりに特定のパターン）に制限する。もし `<all_urls>` が絶対に必要な場合は、なぜそれが必要なのかをマニフェストの説明に明記する。

### IMP-DEVTEXT-06: グラフビューアの検索とフィルタリング
- **дляそのために:** 大きなグラフで特定のノードやエッジを見つけやすくする
- **実装:** グラフビューアに検索バーを追加し、ノードラベルやIDに基づいてフィルタリングする機能を実装する。また、ノードタイプ（シグナル、エフェクトなど）によるフィルタリングも追加する。

### IMP-DEVTEXT-07: ダークモード/ライトモードの切り替え
- **дляそのために:** ユーザーの好みに応じてインターフェースを調整する
- **実装:** CSS カスタムプロパティを使用してテーマを定義し、ユーザーがダークモードとライトモードを切り替えられるオプションを追加する。現在の設定を `localStorage` に保存し、次回起動時に適用する。

### IMP-DEVTEXT-08: データのエクスポート機能
- **дляそのために:** ユーザーが診断や共有のためにデータを保存できるようにする
- **実装:** グラフビューアとポップアップの両方に「エクスポート」ボタンを追加し、現在のデータを JSON ファイルとしてダウンロードできるようにする。ポップアップでは、すべてのタブのデータを統合してエクスポートする。

### IMP-DEVTEXT-09: ツ0: アクセシビリティの向上
- **дляそのために:** 障害を持つユーザーもアクセスできるようにする
- **実装:** ARIA ラベルを追加し、キーボードナビゲーションをサポートし、色のコントラストを WCAG ガイドラインに適合させる。また、スクリーンリーダー向けに説明を追加する。

### IMP-DEVTEXT-10: テストの自動化
- **дляそのために:** リグレッションを防ぎ、品質を確保する
- **実装:** ユニットテストとエンドツーエンドテストを追加し、CI/CD パイプラインに統合する。特に、メッセージパッシングとデータレンダリングのロジックをテストする。

## ۶. نتیجه‌گیری کلی

پکیج `devtools-extension` زینیت فریم‌ورک notion20242424 對応する Chrome 拡張機能であり、開発者がアプリケーションのリアクティビティシステムを可視化およびデバッグするための強力なツールセットを提供します。この拡張機能は、`@zenith/devtools` フックを介してランタイムと統合され、シグナル、エフェクト、ディレクティブ、DOM、コンポーネント、および v1.0 フィーチャー（zen-static、リソースの破棄、キャッシュ統計、SSRストアなど）に関する詳細な情報を表示します。

このパッケージの強み：
- ランタイムとのシームレスな統合（`window.__ZENITH__` フックを通じて）
- 包括的なデータ表示（5つのメインタブとv1.0フィーチャータブ）
- インタラクティブな依存グラフビューア（スタンドアロンおよびポップアップ内）
- リアルタイム更新（ポーリングベース）
- カスタム通知とデータクリア機能
- 良好なドキュメントとコメント（特に機能とバグ修正に関するコメント）

主な改善点：
- 更新間隔を設定可能にするか、プッシュベースのメカニズムに移行する
- グラフビューアにズーム機能を追加する
- エラーハンドリングを改善し、より具体的なフィードバックを提供する
- ホストパーミッションを制限してセキュリティとプライバシーを向上させる
- パフォーマンスを最適化（特に大きなデータセットに対して）
- アクセシビリティと国際化（現在はペルシャ語（Farsi）でハードコーディングされている）を向上させる
- テストを追加して信頼性を確保する
