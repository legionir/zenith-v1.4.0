**نسخه:** v1.3.0 | **بسته:** `@zenith/compiler`

---

## ۱. خلاصه پکیج

پکیج `compiler` responsible for ahead-of-time (AOT) compilation of Zenith HTML templates to optimized JavaScript render functions. This package transforms declarative template syntax into imperative DOM manipulation code, significantly improving runtime performance by eliminating the need for runtime tree-walking and interpretation for many directive types.

The compiler performs:
- Static analysis to distinguish static vs. dynamic template parts
- Code generation for efficient DOM operations
- Tree shaking of unused directives
- Template caching for improved development experience

## ۳. باگ‌ها و مشکلات

### BUG-COMP-01: Structural Directive Conflict Detection Incomplete
- **شدت:** متوسط
- **محل:** `src/compiler.ts` - خطوط 97-101 (تعیین direttiveهای ساختاری)
- **説明:**現在の実装では、`zen-for` と `zen-if/zen-else-if/zen-else` の競合をチェックしていますが、同じ要素上に複数の構造的ディレクティブ（例: `zen-if` と `zen-show` の組み合わせ）が存在する状況を適切に処理していません。これは予期しないレンダリング動作を引き起こす可能性があります。
- **提案の修正:** 構造的ディレクティブ（`zen-if`, `zen-show`, `zen-for`, `zen-else-if`, `zen-else`）が互いに排他的であることを強制するより包括的なチェックを実装し、競合が発生した場合は明確な警告またはエラーを出してください。

### BUG-COMP-02: Недостаток оптимизации для статических атрибутов в циклах
- **しと:** 中
- **場** `src/compiler.ts` - 行401-402 (zen-bindコンパイル)
- **説明:**オブジェクト構文の `zen-bind:class="{ active: $isActive }"` がコンパイルされる場合、現在の実装は各バインディングごとに別々の Effect を生成します。これにより、同じ式に依存する複数のクラスバインディングがある場合に不要な再計算が発生する可能性があります。
- **提案の修正:** 同じ式に依存する複数のクラスバインディングを1つのEffectに結合し、変更検出の効率を向上させます。

### BUG-COMP-03: Проблемы с экранированием в zen-html-trusted
- **шп:** Высокий
- **Место:** `src/compiler.ts` - 行318-349 (zen-html-trustedコンパイル)
- **説明:**`zen-html-trusted` ディレクティブは、`sanitizeHTMLTrusted` が未定義である場合、`sanitizeHTML` にフォールバックします。ただし、このフォールバックメカニズムは、`sanitizeHTMLTrusted` が `null` または他の falsy 値である場合でも作動する可能性があり、これは意図しないサニタイズ動作を引き起こす可能性があります。
- **提案の修正:** フォールバック条件を強化し、`typeof sanitizeHTMLTrusted === 'function'` という明示的なチェックのみにフォールバックを制限してください。

### BUG-COMP-04: Недостаток валидации для zen-for式
- **shiti:** 中
- **Место:** `src/compiler.ts` - 行456-460 (zen-for式解析)
- **説明:**zen-forディレクティブの正規表現パースは、複雑な式（フィルタリングやマッピング関数を含むなど）をうまく処理しません。これにより、コンパイル時にディレクティブが誤ってランタイム処理にフォールバックする可能性があります。
- **提案の修正:** zen-for式の構文解析に、より堅牢なパーサー（既存のexpressionパーサーを再利用する可能性あり）を使用して、複雑なフィルタリングおよびマッピング操作を適切に処理してください。

### BUG-COMP-05: Неэффективная обработка статического текста в zen-for テンプレート
- **しと:** 低
- **Место:** `src/compiler.ts` - 行506-509 (zen-for テンプレートのインナーハMLの埋め込み)
- **説明:**zen-forディレクティブをコンパイルするとき、現在の実装ではテンプレート要素のinnerHTML全体を文字列リテラルとして埋め込みます。これは、大きなテンプレートでは生成されたコードサイズが不必要に大きくなる可能性があります。
- **优化建议:** ゼンフォーティエンプレートのスタティックコンテンツに対して、単項文字列埋め込みよりも効率的なアプローチを検討してください—例えば、テンプレート関数を生成するか、異なるテンプレート戦略を使用してください。

### BUG-COMP-06: Недостаток поддержки для ключевых выражений в zen-for
- **шар:** Средний
- **Место:** `src/compiler.ts` - 行465-496 (zen-key 処理)
- **説明:**現在のzen-key式の処理は、単純なドット表記（`item.id`）といくつかのフォールバックケースに依存しています。これは、より複雑なキー式（`item.user.profile.id` や計算されたキーなど）を適切に処理することができません。
- **提案の修正:** キー式の解析を改善して、完全な式パーサー（既存の表現パーサーの再利用を可能とする）を使用し、複雑なキー式を適切に処理するようにしてください。

### BUG-COMP-07: Неподдерживаемые директивы ловили тихо
- **шар:** Высокий
- **Место:** `src/compiler.ts` - 行579-580 (compileCompilableDirectiveの返却値)
- **説明:**`compileCompilableDirective` 関数が `false` を返す場合、ディレクティブはサポートされていないとしてマークされます。ただし、関数が適切な理由なしに `false` を返す可能性のあるエッジケースがあり、これによりディレクティブがランタイム処理のために誤って保存される可能性があります（意図しない動作の可能性があります）。
- **提案の修正:** `compileCompilableDirective`関数に追加の検証を追加し、サポートされていないディレクティブが明確に識別および処理されるようにしてください。

### BUG-COMP-08: Недостаток strictモードでのエラーメッセージの詳細
- **пауза:** Низкий
- **Место:** `src/compiler.ts` - 行595-596 (厳格モードの例外処理)
- **説明:**厳格モードが有効な場合、`preserveDirectiveForRuntime` からの警告が例外としてスローされますが、これらの例外メッセージは堆栈トレースやディレクティブが登場する具体的なテンプレートの場所などのコンテキストが欠如している場合があります。
- **提案の修正:** 厳格モードでのエラーメッセージを強化し、ファイル名、行番号、および可能な場合、問題のあるディレクティブの周囲のコードスニペットなどの追加のコンテキスト情報を含めてください。

## ۴. پیشنهادات ارتقا

### IMP-COMP-01: 增量编译支持
- **для чего:** 动态模板更新时的开发体验改善和重新编译时间减少
- **実装:** ファイルシステムウォッチャー（`chokidar`または`fs.watch`を使用）を追加し、テンプレートファイルの変更を監視し、変更されたテンプレートのみを再コンパイルします

### IMP-COMP-02: テンプレートコンパイルのソースマップ生成
- **для чего:** 生成されたJavaScriptを元のテンプレートにデバッグのためにマッピングする
- **実装:** コンパイルプロセス中にソースマップを生成し、生成されたコード内の位置を元のテンプレートマークアップにマッピングします

### IMP-COMP-03: テンプレート分析および最適化レポート
- **для aufgrund:** 开发者了解其模板的编译效率并识别优化机会
- **実装:** コンパイル結果に、静的 vs 動的コンテンツの割合、使用されなかったディレクティブ、および潜在的なパフォーマンスボトルネックに関する情報を含む詳細なレポートを追加してください

### IMP-COMP-04: プラグイン可能なディレクティブハンドラー
- **для 때문이었다:** 外部パッケージがコンパイラにカスタムディレクティブサポートを追加できるようにする
- **実装:** ディレクティブコンパイラのためのプラをプラグイン可能なアーキテクチャにリファクターし、外部モジュールが特定のディレクティブタイプのコンパイルロジックを登録できるようにします

### IMP-COMP-05: Tree Shakingの改善
- **дляそのために:** コンパイル済みテンプレートから使用されていないディレクティブをより積極的に削除してください
- **実装:** ディレクティブ使用状況のより正確な追跡を実装し、定義されているが実際にテンプレートで参照されていないディレクティブを除去します

### IMP-COMP-06: ความร้อน再加载支持
- **дляそのために:** デベロッパーが手動でページをリロードすることなくテンプレートの変更を見ることができるようにする
- **実装:** Viteプラグインとの統合を通じてホットモジュール置換（HMR）をサポートし、コンパイル済みテンプレートのランタイム更新を可能にします

### IMP-COMP-07: WebAssemblyコンパイルオプション（実験的）
- **дляそのために:** 非常に大きなテンプレートのためのパフォーマンスの可能性を探る
- **実装:** オプションのWebAssemblyバックエンドを追加し、非常に大きなまたは複雑なテンプレートではコンパイル済みJavaScriptではなくWebAssemblyモジュールを生成することを検討してください

## ۶. نتیجه‌گیری کلی

پکیج `compiler` زِینِت فریم‌ورک کی rendimiento आदि성能的核心组成부분이다。テンプレートを命令型JavaScriptに変換することで、実行時のオーバーヘッドを大幅に削減し、特に静的コンテンツが多いアプリケーションでは特にそうだろう。

このパッケージの強점 включают:
- 良質な構造とモジュール設計
- 包括的なディレクティブサポート（コンパイル可能およびランダイムのみ）
- 慎重な安全性の考慮（特に `zen-html` および `zen-html-trusted` に対して）
- 良いエラーハンドリングと警告システム

重要な改善点에는 다음과 같은 것이 포함됩니다:
更好的结构化指令冲突检测
パフォーマンス最適化のためのバインディングの集約
フォールバックメカニズムの改善（zen-html-trusted）
式パースの強化（zen-forとzen-key）
宣言されていないが実際には使用されていないディレクティブのためのより良いツリーシェーキング

**امتیاز کلی: 8/۱۰** ( хорошо arquitetado compilador com espaço para otimizações e aprimoramentos de experiência do desenvolvedور)
