# داشبورد مدیریتی Zenith (دمو — #113)

داشبورد نمایشی با mock API کاربران/نقش‌ها و RBAC واقعی سمت API.

## اجرا (یک دستور، دادهٔ ثابت)

از ریشهٔ مخزن (پس از build پکیج‌ها):

    npx serve . -l 8089
    # سپس: http://127.0.0.1:8089/dashboard/index.html

یا با سرور e2e:

    node scripts/e2e-server.mjs

## چه چیزی واقعی است و چه چیزی نمونه؟

- **Mock API واقعی است** (`dashboard/src/mock-api.js` روی موتور `@zenith/mock`):
  دادهٔ اولیهٔ قطعی (۳ کاربر: admin/editor/viewer)، session/refresh با توکن، و
  اعمال 401/403 روی هر مسیر حساس — از جمله `DELETE /api/users/:id` (نیازمند
  `users:delete`؛ حذف خود ممنوع) و `GET /api/admin/stats` (نیازمند
  `stats:read`). مخفی‌شدن دکمه‌ها در UI **مجوز نیست**: API هر عملیات غیرمجاز
  را رد می‌کند و e2e همین را می‌آزماید.
- **نقش‌ها و دسترسی‌ها واقعی‌اند** (`PermissionManager` + `zen-permission` با
  fail-closed؛ بدون manager هیچ دکمهٔ حساسی دیده نمی‌شود).
- **توکن‌ها و رمزها نمایشی‌اند**: توکن `token-<username>` قطعی و رمزها
  plaintext داخل کد دمو هستند. این دمو backend واقعی، پرداخت و inventory
  ندارد و هیچ‌چیز آن نباید الگوی احراز هویت production دانسته شود.

## محدودیت امنیتی صریح

کنترل‌های frontend (مخفی‌شدن دکمه، `zen-if`) فقط UI هستند و با ویرایش DOM/JS
قابل دور زدن‌اند — دقیقاً به همین دلیل mock API هم روی هر درخواست مجوز را
دوباره بررسی می‌کند. گارد مسیر سمت-کاربر (router guard) در این پوستهٔ دمو
نیست؛ سطح قابل‌اتکای enforce همین APIهاست و تست‌ها همان را پوشش می‌دهند.
