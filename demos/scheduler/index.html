۱. Automatic Batching با Microtask

وقتی ۱۰۰ بار پشت سر هم signal.set() صدا می‌زنید، بدون Scheduler، DOM ۱۰۰ بار آپدیت می‌شد. Scheduler با Microtask، تمام Effectهای یک تیک را در یک flush اجرا می‌کند — یعنی DOM فقط ۱ بار آپدیت می‌شود (با مقدار نهایی).

امتحان کنید: روی «حلقه ۱۰۰ تایی» کلیک کنید. Effectها فقط ۱ بار (نه ۱۰۰ بار) اجرا می‌شوند — DOM فقط ۱ بار آپدیت می‌شود.

۲. Priority Queue — urgent → normal → idle

Scheduler از سه سطح اولویت پشتیبانی می‌کند: urgent (کار حیاتی مثل navigation)، normal (آپدیت DOM معمولی)، idle (analytics، logging). در هر flush، Effectها به ترتیب urgent → normal → idle اجرا می‌شوند.

ترتیب ثبت: idle → normal → urgent (عمداً برعکس). ترتیب اجرا: urgent → normal → idle ← باید اینطور ببینید.

(روی دکمه کلیک کنید)
// مستقیم از @zenith/scheduler:
import { scheduleEffect, flushSync } from '@zenith/scheduler';

scheduleEffect(() => log('idle ran'),   'idle');
scheduleEffect(() => log('normal ran'), 'normal');
scheduleEffect(() => log('urgent ran'), 'urgent');
flushSync();  // اجرای synchronous
// ترتیب اجرا: urgent → normal → idle

۳. flushSync() — اجرای Synchronous

معمولاً Scheduler از Microtask استفاده می‌کند (یعنی Effectها در پایان تیک اجرا می‌شوند). اما گاهی لازم است Effectها همین حالا اجرا شوند — مثلاً بعد از یک state.set() در یک Event Handler. این کار با flushSync() انجام می‌شود. این تابع re-entrancy-safe است. 

count.set(42);
// اینجا DOM هنوز ۰ است — Effectها در microtask بعدی اجرا می‌شوند.

count.set(99);
flushSync();
// اینجا DOM با مقدار ۹۹ آپدیت شده — Effectها همین‌جا اجرا شدند.

۴. محافظت در برابر Infinite Loop

اگر یک Effect در حین اجرا، خودش را دوباره schedule کند (مثلاً با خواندن و نوشتن همان Signal)، می‌تواند Infinite Loop بسازد. Scheduler این را تشخیص می‌دهد: بعد از ۱۰۰۰ iteration، اجرا را متوقف می‌کند و یک warning در console چاپ می‌کند. 

// این Effect خودش را trigger می‌کند:
let runaway = signal(0);
effect(() => {
  const v = runaway.get();  // read
  runaway.set(v + 1);       // write → trigger خودش
});
// بعد از ۱۰۰۰ iteration، Scheduler متوقف می‌شود.

بعد از کلیک، console مرورگر را باز کنید — warning [Zenith Scheduler] Flush exceeded 1000 iterations... را خواهید دید.

خلاصه

Scheduler با Microtask batching، تعداد DOM updates را از N به ۱ کاهش می‌دهد. Priority Queue تضمین می‌کند که کارهای حیاتی (مثل navigation) قبل از DOM updates، و DOM updates قبل از analytics اجرا شوند. flushSync برای مواردی که نیاز به synchronous update دارید. Infinite loop protection از قفل شدن اپلیکیشن جلوگیری می‌کند.
