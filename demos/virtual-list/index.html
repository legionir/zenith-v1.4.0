📊 Virtual List

اسکرول مجازی برای ۱۰٬۰۰۰+ آیتم — فقط ~۲۰ آیتم در DOM — با static و dynamic heights

zen-virtual-list 10K items static-heights dynamic-heights ResizeObserver binary-search scroll-to-index

۱. Static Heights — ۱۰٬۰۰۰ آیتم، هر کدام ۴۰px

ارتفاع ثابت: فقط zen-item-height="40" کافی است. با این حال، فقط ~۲۰ آیتم به‌علاوه‌ی buffer در DOM رندر می‌شوند (به‌جای ۱۰٬۰۰۰). در ابزار Developer مرورگر، تعداد نودهای DOM را بررسی کنید.

total: 10000 item height: 40px visible: — rendered: — 
<div zen-virtual-list="$items" zen-item-height="40" zen-buffer="5">
  <template>
    <div class="vlist-row" style="height:40px;">
      <span zen-text="$index"></span>
      <span zen-text="$item.name"></span>
    </div>
  </template>
</div>

۲. Dynamic Heights — ارتفاع متغیر با ResizeObserver

با zen-dynamic-heights="true" ارتفاع هر آیتم توسط ResizeObserver اندازه‌گیری می‌شود. برخی آیتم‌ها توضیحات بلند دارند (هر ۷ آیتم یکبار) و برخی فقط یک خط. موقعیت هر آیتم با prefix sum و binary search محاسبه می‌شود.

total: 10000 item height (est.): 60px visible: — rendered: — 
<div zen-virtual-list="$items"
     zen-dynamic-heights="true"
     zen-item-height="60"  <!-- ارتفاع تخمینی اولیه -->
     zen-buffer="5">
  <template>
    <div class="vlist-row">
      <span zen-text="$item.name"></span>
      <p zen-if="$item.description" zen-text="$item.description"></p>
    </div>
  </template>
</div>

۳. Scroll to Index — پرش به موقعیت دلخواه

با کلیک روی دکمه، به آیتم مورد نظر در لیست static پرش کنید.

۵. مقایسه — بدون Virtual List

برای مقایسه، می‌توانید همان ۱۰٬۰۰۰ آیتم را بدون virtual-list رندر کنید. این کار بسیار کندتر است (هم در رندر اولیه و هم در اسکرول). در DevTools، تعداد DOM nodes و memory usage را مقایسه کنید.

⚠️ هشدار: این کار ممکن است چند ثانیه طول بکشد و مرورگر را کند کند.

خلاصه

zen-virtual-list با فقط رندر کردن visible items (~۲۰ به‌جای ۱۰٬۰۰۰) عملکرد را به‌شدت بهبود می‌بخشد. با zen-item-height برای ارتفاع ثابت و zen-dynamic-heights="true" برای ارتفاع متغیر (با ResizeObserver و binary search) کار می‌کند.
