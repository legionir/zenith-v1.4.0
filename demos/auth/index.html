🔐 Auth Flow

ورود، مدیریت توکن، refresh خودکار و route guard — با کلاس Auth

۱. فرم ورود

با auth.login({ email, password }) درخواست POST به /api/auth/login ارسال می‌شود. در صورت موفقیت، token، refreshToken، user و expiresIn در Signal ذخیره می‌شوند. fetch در این دمو mock شده است.

⚠️ خطا:

💡 mock سرور: هر ایمیل معتبر (شامل @ و .) با هر رمزی قبول می‌شود. نام کاربر بازگشتی از local-part ایمیل ساخته می‌شود. ایمیل نامعتبر (مثل dddddd) خطا می‌دهد. expiresIn = ۱۰ ثانیه + refresh خودکار قبل از آن.

۲. اطلاعات کاربر — نمایش واکنش‌گرا

پس از ورود، $auth.user برابر با آبجکت کاربر می‌شود. این بخش با zen-if="$auth.user" نمایش داده می‌شود.

۴. شبیه‌سازی Auto-Refresh

توکن این دمو ۱۰ ثانیه اعتبار دارد و refreshThreshold = 5 تنظیم شده. یعنی ۵ ثانیه قبل از انقضا، auth.refresh() به‌صورت خودکار فراخوانی می‌شود و توکن جدید گرفته می‌شود. در شمارش‌معکوس زیر، وقتی به ۵ ثانیه برسد، refresh رخ می‌دهد.

— ثانیه تا انقضای توکن
✅ تاکنون بار توکن به‌صورت خودکار refresh شده است. 
const auth = createAuth({
  loginUrl: '/api/auth/login',
  meUrl: '/api/auth/me',
  refreshUrl: '/api/auth/refresh',
  autoRefresh: true,
  refreshThreshold: 5,  // 5 ثانیه قبل از expiry
});
// expiresIn در mock fetch برابر 10 ثانیه است.

خلاصه

        

          Auth یک Signal از وضعیت احراز هویت نگه می‌دارد.
          متدهای login، logout، refresh و fetchUser فراهم هستند.
          توکن‌ها در localStorage، sessionStorage، cookie یا memory قابل ذخیره‌اند.
          autoRefresh با timeout، قبل از انقضای توکن، refresh را به‌صورت خودکار فراخوانی می‌کند.
