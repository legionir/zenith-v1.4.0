PermissionManager RBAC zen-role zen-permission any:/all: super-admin-bypass createGuard

۱. تعویض نقش کاربر

با pm.setUserAccess(roles, permissions) دسترسی‌های کاربر فعلی را تنظیم کنید. در بخش‌های پایین، محتوای واکنش‌گرا به نقش شما تغییر می‌کند.

۳. دایرکتیو zen-role="admin"

این بخش فقط وقتی نمایش داده می‌شود که کاربر نقش admin داشته باشد (یا super-admin باشد).

✅ پنل مدیریت

این محتوا فقط برای کاربرانی با نقش admin قابل مشاهده است.

<div zen-role="admin">
  <!-- محتوای ادمین -->
  <template zen-fallback>
    <p>دسترسی فقط برای ادمین</p>
  </template>
</div>

۴. zen-role="any:admin,editor" — حداقل یکی

این بخش برای کاربرانی که نقش admin یا editor داشته باشند نمایش داده می‌شود.

✅ بخش ویرایش محتوا

این بخش برای ادمین یا ویراستار قابل مشاهده است.

<div zen-role="any:admin,editor">
  <!-- admin یا editor -->
</div>

۵. zen-role="all:admin,verified" — همه‌ی نقش‌ها

این بخش فقط برای کاربری که هم admin هم verified داشته باشد نمایش داده می‌شود. در این دمو، نقش Admin شامل هر دو است.

✅ پنل ادمین تایید‌شده

این محتوا فقط برای کاربری با نقش‌های admin و verified (هر دو) قابل مشاهده است.

<div zen-role="all:admin,verified">
  <!-- admin و verified -->
</div>

۶. دایرکتیو zen-permission="users:delete"

این دکمه فقط برای کاربری که permission users:delete داشته باشد (یا super-admin باشد) نمایش داده می‌شود.

<button zen-permission="users:delete">حذف کاربر</button>

۷. zen-permission="any:users:edit,users:create"

این بخش برای کسی که حداقل یکی از users:edit یا users:create را داشته باشد (یا super-admin باشد) نمایش داده می‌شود.

<div zen-permission="any:users:edit,users:create">
  <button>ویرایش</button>
  <button>ایجاد</button>
</div>

۸. Super-Admin Bypass — همه‌چیز مجاز

وقتی کاربر نقش super-admin داشته باشد، تمام بررسی‌های permission و role بدون توجه به لیست واقعی، true برمی‌گردند. در این دمو، super-admin هیچ permission مستقیمی ندارد اما همه‌چیز برایش مجاز است.

✅ شما super-admin هستید — همه‌ی permission ها (حتی system:format-server) بدون تعریف مجاز هستند. 
// در PermissionManager:
can(permission) {
  if (state.isSuperAdmin) return true;  // bypass!
  return state.permissions.includes(permission);
}
hasRole(role) {
  if (state.isSuperAdmin) return true;  // bypass!
  return state.roles.includes(role);
}

۹. createGuard — حفاظت از Route

با createGuard('admin:access', 'permission') یک تابع guard ساخته می‌شود که می‌توان آن را قبل از ورود به یک route فراخوانی کرد.

guard('admin:access') = — guard('admin' as role) = — guard('super-only' as role) = — 
import { createGuard } from '@zenith/permission';
const adminGuard = createGuard('admin:access', 'permission');
if (!adminGuard()) {
  Zen.navigate('/login');  // رد کردن
}

خلاصه

PermissionManager با یک Signal از نقش‌ها/دسترسی‌ها نگه می‌دارد. دایرکتیوهای zen-role و zen-permission با expression syntax (پشتیبانی از any: و all:) کار می‌کنند. نقش super-admin به‌صورت خودکار همه‌ی بررسی‌ها را bypass می‌کند. با createGuard می‌توان route guard ساخت.
