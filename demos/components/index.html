🧩 Components & Slots

کامپوننت‌های Light DOM با Props، Slots و Context Inheritance — تعریف با <zen-component>

zen-component props slots nested reactive-props light-dom

۱. کامپوننت ساده

یک کامپوننت با <zen-component name="zen-greeting"> تعریف می‌شود. قالب آن درون <template> قرار می‌گیرد. وقتی تگ <zen-greeting> در DOM ظاهر می‌شود، walker آن را تشخیص داده و قالب را جایگزین می‌کند. 

<zen-component name="zen-greeting">
  <template>
    <div class="greeting">سلام، دنیا!</div>
  </template>
</zen-component>

<zen-greeting></zen-greeting>  <!-- استفاده -->

۲. Props با Literal Attribute

attribute های معمولی روی تگ کامپوننت به‌صورت literal string به Context محلی اضافه می‌شوند. مثلا name="علی" در template به‌صورت $name قابل دسترسی است.

محتوای Slot پیش‌فرض — این متن از محل استفاده کامپوننت می‌آید.

 
<user-card name="علی" age="25">
  <p>محتوای Slot پیش‌فرض</p>
</user-card>

<!-- داخل template: zen-text="$name" و zen-text="$age" -->

۳. Slots — پیش‌فرض و نام‌گذاری شده

کامپوننت user-card دو slot دارد: پیش‌فرض و actions. فرزندان بدون slot به slot پیش‌فرض می‌روند؛ فرزندان با slot="actions" به slot نام‌گذاری شده. محتوای slot با Context والد ارزیابی می‌شود (نه Context محلی کامپوننت).

این متن در slot پیش‌فرض می‌رود.

 
<user-card name="زهرا" age="30">
  <p>این متن در slot پیش‌فرض می‌رود.</p>
  <button slot="actions" zen-action="slotClick">...</button>
</user-card>

۴. Reactive Props با prop:

با پیشوند prop:، مقدار prop به‌صورت یک Expression در parentContext ارزیابی می‌شود. این یعنی اگر Expression وابسته به یک Signal باشد، با تغییر Signal، prop هم به‌صورت reactive آپدیت می‌شود. در این مثال prop:name="$user.name" و prop:age="$user.age" به Signal کاربر متصل‌اند.

user.name = user.age =

این محتوا از parent می‌آید. نام داخل کارت از $user.name می‌خواند.

 
<user-card prop:name="$user.name" prop:age="$user.age">
  <!-- prop:name یک Expression است که در parentContext ارزیابی می‌شود -->
</user-card>

۵. Nested Components (کامپوننت تو در تو)

داخل template یک کامپوننت می‌توان از کامپوننت‌های دیگر استفاده کرد. در این مثال، profile-widget داخل خودش یک user-card دارد. Context محلی والد به‌صورت خودکار به فرزند ارث می‌رسد — پس $user در profile-widget هم در دسترس است. 

<zen-component name="profile-widget">
  <template>
    <user-card prop:name="$user.name" prop:age="$user.age">
      <button slot="actions" zen-action="bumpAge">تولد +۱</button>
    </user-card>
  </template>
</zen-component>

۶. Multiple Instances — چندین نمونه با داده‌ی متفاوت

می‌توان همان کامپوننت را با داده‌های متفاوت چندین بار استفاده کرد. هر نمونه Context محلی مستقل خودش را دارد. اینجا چهار user-card با literal props متفاوت داریم.

خلاصه

<zen-component> برای تعریف، تگ سفارشی برای استفاده. Props با prop:name="expr" (Expression) یا name="literal" (رشته‌ی ثابت). Slots با <slot> و <slot name="x">. Context والد به‌صورت خودکار به فرزند ارث می‌رسد — پس Nested Components کار می‌کنند. Light DOM (نه Shadow DOM) یعنی Event Delegation و CSS سراسری هم کار می‌کنند.
