۱. فرم ثبت‌نام — اعتبارسنجی زنده

فرم زیر با FormStore ساخته شده. هر فیلد rules خاص خودش را دارد. با تایپ کردن، validation همزمان اجرا می‌شود؛ خطا فقط وقتی نمایش داده می‌شود که فیلد touched باشد.

rules: requiredmin:3max:30
rules: requiredemail
rules: requirednumbermin:18max:120
rules: url
rules: requiredmin:8
rules: requiredequalsField:password
const form = new FormStore({
  name:             { initial: '', rules: 'required,min:3,max:30' },
  email:            { initial: '', rules: 'required,email' },
  age:              { initial: '', rules: 'required,number,min:18,max:120' },
  website:          { initial: '', rules: 'url' },
  password:         { initial: '', rules: 'required,min:8' },
  passwordConfirm:  { initial: '', rules: 'required,equalsField:password' },
});

// در State قرار می‌دهیم تا در Expression Engine در دسترس باشد:
const state = { form: form.signal };

۲. Cross-field Validation — equalsField

فیلد «تکرار رمز عبور» با rule equalsField:password چک می‌کند که با «رمز عبور» برابر باشد. وقتی رمز عبور را تغییر می‌دهید، FormStore به‌صورت خودکار passwordConfirm را دوباره اعتبارسنجی می‌کند (داخل _updateField).

امتحان کنید: رمز عبور را وارد کنید، تکرار را مطابقت دهید، سپس رمز عبور را تغییر دهید — خطای «مقادیر مطابقت ندارند» روی تکرار ظاهر می‌شود. 

// در Action handler:
Zen.action('onPasswordInput', ({ state, event }) => {
  state.form.setValueAndTouch('password', event.target.value);
});
// FormStore خودش cross-field را re-validate می‌کند.

۳. Submit Handler — فقط وقتی معتبر

متد form.submit(handler) اول همه فیلدها را touch می‌کند، sync validation را اجرا می‌کند، سپس async validation را. اگر همه معتبر باشند، handler را با values فراخوانی می‌کند. در غیر این صورت، handler اجرا نمی‌شود و خطاها نمایش داده می‌شوند. 

const ok = await form.submit(async (values) => {
  console.log('Form submitted:', values);
  // فراخوانی API...
  await api.register(values);
});
if (!ok) console.log('Form invalid — submission skipped.');

۴. Async Validation — بررسی نام کاربری یکتا

با defineAsyncRule می‌توان rule های async تعریف کرد (مثل بررسی uniqueness از سرور). FormStore این rule ها را با debounce 300ms اجرا می‌کند. در حین اجرا، validating فیلد true می‌شود.

⏳ در حال بررسی...
rules: requiredmin:3usernameUnique (async)
defineAsyncRule('usernameUnique', async (value) => {
  // شبیه‌سازی call به سرور
  await new Promise(r => setTimeout(r, 400));
  const taken = ['ali', 'mohammad', 'reza', 'admin'];
  // مقایسه‌ی case-insensitive:
  const lower = String(value).toLowerCase();
  return taken.some(t => t.toLowerCase() === lower)
    ? { valid: false, error: 'این نام کاربری قبلاً گرفته شده', rule: 'usernameUnique' }
    : { valid: true, error: null };
});

۵. مرجع Rule های Built-in

این rule ها به‌صورت پیش‌فرض در دسترس هستند. با ویرگول از هم جدا می‌شوند: "required,email,min:8".

required email url min:N max:N pattern:regex equals:value equalsField:name number integer positive negative date phone creditCard

برای Rule های سفارشی: defineRule('myRule', (value, allValues, param) => ({valid, error, rule})). برای Rule های async: defineAsyncRule('myAsyncRule', async (value, allValues, param) => ...).
