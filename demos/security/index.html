🔒 امنیت و Sanitizer

تست تعاملی Sanitizer روی حملات XSS واقعی — تفاوت zen-text (متن خام) و zen-html (HTML پاکسازی‌شده)

zen-html sanitizer XSS DOMParser

۱. تست تعاملی Sanitizer

HTML آلوده را در textarea وارد کنید (یا یکی از Presetها را انتخاب کنید). پنل سمت چپ نشان می‌دهد اگر با zen-text (یعنی textContent) رندر شود چه می‌شود (امن — هیچ کد اجرا نمی‌شود). پنل سمت راست نشان می‌دهد اگر با zen-html رندر شود چه می‌شود — اما Sanitizer از اجرای کد مخرب جلوگیری می‌کند.

🔴 zen-text (متن خام — textContent)
🟢 zen-html (HTML پاکسازی‌شده — Sanitizer)
تعداد alert های اجرا شده: 0 ← حمله‌ی XSS موفق بود! ❌ ← هیچ حمله‌ای موفق نشد ✅

۲. چرا Sanitizer؟

zen-html در فریم‌ورک Zenith همیشه قبل از تزریق به DOM، مقدار را از sanitizeHTML() عبور می‌دهد. این تابع از DOMParser استفاده می‌کند که برخلاف innerHTML هیچ اسکریپتی را اجرا نمی‌کند. سپس تگ‌ها و attributeهای خطرناک را حذف می‌کند. 

// پشت صحنه‌ی zen-html:
import { sanitizeHTML } from '@zenith/security';

const dirtyHtml = '<img src=x onerror=alert(1)>';
const cleanHtml = sanitizeHTML(dirtyHtml);
// ← '<img src="x">'  (onerror حذف شد)

element.innerHTML = cleanHtml;  // ایمن است

۳. حملات بلاک‌شده توسط Sanitizer

Sanitizer این دسته از حملات را به‌طور پیش‌فرض بلاک می‌کند:

[BLOCKED] <script> tags → حذف کامل
[BLOCKED] <iframe>, <object>, <embed> → حذف کامل
[BLOCKED] onclick, onerror, onload, … (on*) → حذف attribute
[BLOCKED] javascript: و vbscript: در href/src → حذف href/src
[BLOCKED] data: URL → حذف href/src
[BLOCKED] <style> با expression() یا url(javascript:) → حذف
[BLOCKED] <svg> با <script> داخلی → پاکسازی فرزندان
[BLOCKED] __proto__, constructor, prototype در attrs → حذف
[BLOCKED] Comment nodes با payloads مخرب → حذف
[ALLOWED] <h3>, <p>, <strong>, <ul>, <li> … → عبور می‌کنند

Defense in Depth: Sanitizer یک لایه‌ی دفاعی است. همیشه روی سرور هم HTML را sanitize کنید و از CSP (Content-Security-Policy) استفاده کنید.

۴. خلاصه

برای رندر متن از کاربر، همیشه از zen-text استفاده کنید (کاملاً امن). اگر باید HTML رندر کنید (مثل نظرات کاربران با فرمت‌بندی)، از zen-html استفاده کنید — این دایرکتیو به‌طور خودکار از sanitizeHTML() عبور می‌کند. هیچ‌وقت innerHTML را دستی با داده‌ی کاربر set نکنید.
