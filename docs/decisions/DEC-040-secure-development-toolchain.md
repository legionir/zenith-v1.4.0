# DEC-040: ابزارهای توسعهٔ رفع‌شده و تفکیک کف Node ابزارها از کتابخانه

- **وضعیت:** پذیرفته‌شده برای remediation W1؛ بازبینی امنیت پیش از انتشار لازم است.
- **تاریخ:** ۲۰۲۶-۱۰-۱۶
- **مرتبط:** #13، #110، #14، DEC-007، DEC-034

## زمینه

Audit تازهٔ prod+dev ده یافته داشت (دو critical، پنج high، سه moderate)؛ prod صفر بود.
Vitest 3 و tinypool و ابزارهای قدیمی glob/braces را نمی‌توان با override خارج از قرارداد
سازگاری به‌طور قابل اتکا امن کرد. ابزار جدید Node بالاتری می‌خواهد، اما این به‌تنهایی دلیل
تغییر بی‌صدای `engines` تمام کتابخانه‌ها نیست.

## گزینه‌ها

نگه‌داشتن ابزار آسیب‌پذیر/override اجباری (رد)، افزایش کف تمام کتابخانه‌ها (ناموجه در این batch)، تفکیک ابزار و runtime با ماتریس صریح (انتخاب).

## تصمیم و دلیل

- توسعه، test runner، hook و گیت‌های معمول با **Node 22.12+ از خط 22 LTS**؛ نمونهٔ اجرا
  Node 22.22.3 است. Vitest/coverage روی 4.1.12، lint-staged روی 16.4.0، Vite روی
  6.4.4 و 7.3.7 در lockfile قفل‌اند؛ هیچ override امنیتی ناسازگار اضافه نشد.
- `engines.node >=18.19` کتابخانه‌ها فعلاً تغییر نمی‌کند. ماتریس build قدیمی
  18.19/20/22 اثبات سازگاری artifact است، **نه توصیهٔ استفادهٔ production از Node EOL**
  و نه وعدهٔ اجرای Vitest 4 یا lint-staged 16 روی Node 18. روی خط قدیمی، npm ممکن است
  برای devDependencyها `EBADENGINE` هشدار دهد؛ تست و hook را با Node توسعه اجرا کنید.
- peer افزونه فقط `^6.4.4 || ^7.3.7` است: major 5 و patchهای قبل از رفع advisory از
  قرارداد پشتیبانی خارج‌اند. مهاجرت در README و راهنمای migration ثبت شده است.
- build واقعی و HTTP dev-server در دو job Vite 6/7 اجرا می‌شوند. نصب peer نامعتبر یا
  patch ناامن باید `ERESOLVE` بدهد. درخواست Vite 8 و HMR/sourcemap پیشرفتهٔ #110
  **باز** می‌ماند؛ این تصمیم به‌معنای تکمیل قرارداد 6/7/8 آن issue نیست.
- audit کامل بدون `|| true` و با `--audit-level=low` گیت مسدودکننده است. صفر audit
  ارزیابی exploitability همهٔ کدها یا ممیزی مستقل #61 نیست.

## پیامدها

CI و مشارکت‌کننده‌ها باید از کف ابزار توسعه پیروی کنند. تغییر سیاست runtime/EOL نیاز به
تصمیم جدا و سنجش مصرف‌کننده دارد. خروج Vite 5 یک تغییر سازگاری ابزار build است و در
changeset افزونه به‌عنوان **major** ثبت می‌شود؛ کوچک‌خواندن این تغییر صرفاً به‌دلیل
«dev-only» بودن درست نیست. به‌دلیل fixed/lockstep group، اجرای version bump و انتخاب
candidate با مالک انتشار هماهنگ شود؛ این batch هیچ نسخه‌ای را عوض یا منتشر نمی‌کند.
نتیجهٔ CI و شواهد هر batch در progress ثبت می‌شود؛ این تصمیم خودش شاهد پاس‌شدن CI نیست.

## پیوست: جای ابزارها و گزارش API (#51/#56)

ابزارهای مرورگر/ویرایشگر workspace خصوصی در `tools/` هستند، نه کتابخانهٔ npm.
بیلد ریشه هر دو مسیر libraries/tools را صریح اجرا می‌کند؛ بسته‌بندی فروشگاهی
ZIP/VSIX جداست و انتشار خودکار نمی‌کند. نام قدیمی workspace VS Code حفظ می‌شود.
برای API، API Extractor روی declaration ساخته‌شده مرجع report امضادار است؛
ممیزی TypeScript graph مکمل آن برای any عمومی است، نه جایگزین report رسمی.
