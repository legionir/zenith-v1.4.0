# حریم خصوصی (#94)

سیاست رسمی Zenith برای داده‌بران‌شناسی (telemetry) در ابزارهای خط فرمان.

## تضمین‌های کلیدی

1. **پیش‌فرض خاموش است.** هیچ‌گاه، در هیچ شرایطی، بدون انتخاب آگاهانهٔ شما هیچ
   داده‌ای از ماشین شما ارسال نمی‌شود. telemetry کاملاً **opt-in** است.
2. **هیچ endpoint پیش‌فرضی وجود ندارد.** حتی پس از فعال‌سازی، بدون تعیین
   `ZENITH_TELEMETRY_ENDPOINT` به‌صورت محلی هیچ درخواست شبکه‌ای انجام نمی‌شود.
3. **Kill switch غالب:** متغیر `ZENITH_TELEMETRY=0` همیشه telemetry را از
   کار می‌اندازد، حتی اگر config فایل فعال باشد.

## نحوهٔ فعال‌سازی/غیرفعال‌سازی

```bash
zenith telemetry on       # فعال‌سازی ثبت‌شده در ~/.zenith/telemetry.json
zenith telemetry off      # غیرفعال
zenith telemetry status   # نمایش وضعیت و منبع تصمیم
ZENITH_TELEMETRY=0 zenith ...   # غیرافعال‌سازی موقت برای هر اجرا
```

## دقیقاً چه داده‌ای ارسال می‌شود؟

اگر — و فقط اگر — telemetry را فعال کرده باشید و یک endpoint معتبر تعریف شده
باشد، هر رویداد فقط این فیلدها را دارد:

| فیلد | شرح |
|---|---|
| `event` | نام رویداد انگلیسی (مثل `build.start`) |
| `zenithVersion` | نسخهٔ پکیج CLI |
| `nodeMajor` | عدد major نسخهٔ Node (مثل `22`) |
| `platform` | `linux` / `darwin` / `win32` |
| `ci` | آیا در محیط CI اجرا می‌شود (`true`/`false`) |

## چه داده‌ای هرگز ارسال نمی‌شود؟

- مسیر فایل یا پوشه (absolute/relative)، نام پروژه، نام کاربر، hostname، IP.
- محتوای هر فایل یا هر عبارت سورس‌کد.
- توکن، کلید API، متغیر محیطی یا هر secret.
- فیلدهای کلیدهایی که به مسیر/نام/توکن شباهت داشته باشند، به‌صورت خودکار توسط
  `sanitizeTelemetryProps` حذف می‌شود.

از برنامه‌نویسان Zenith انتظار می‌رود هنگام افزودن هر رویداد جدید، همین سند
را نیز به‌روزرسانی کنند و از `sanitizeTelemetryProps` برای props استفاده نمایند.

## اجرای خطای ارسال

اگر endpoint پاسخ ندهد یا خطا بدهد، هیچ خروجی مرئی به کاربر نمایش داده
نمی‌شود و برنامهٔ CLI به تاخیر/شکست نمی‌خورد (best-effort fire-and-forget).
